# अगले सत्र की तैयारी का कार्य

अगले सत्र में हम एक वेब पेज से मिले उत्तर की जाँच करेंगे और परिणाम, तारीख व समय को एक रिपोर्ट में दर्ज करेंगे. आप यह प्रक्रिया अपनी रिपॉज़िटरी में चलाएँगे. इसके लिए ज़रूरी दो फ़ाइलें अपने Codespace में पहले से तैयार कर लें. इसमें लगभग 10 मिनट लगेंगे. कुछ जमा नहीं करना है.

## क्या तैयार करना है

`pre_day2` नाम के फ़ोल्डर में ये दो फ़ाइलें बनाएँ.

- `pre_day2/template.md` — रिपोर्ट के पाठ का टेम्पलेट
- `pre_day2/generate.sh` — टेम्पलेट से रिपोर्ट बनाने वाली स्क्रिप्ट

इनकी सामग्री इस पेज पर नीचे दी गई है. इन्हें पढ़ना और चलाना अगले सत्र में होगा. अभी केवल फ़ाइलें तैयार करना पर्याप्त है.

## क्या करना है

1. आज इस्तेमाल किया गया Codespace खोलें. यदि उसका टैब खुला है, तो उस पर लौटें. यदि बंद कर दिया था, तो GitHub पर अपनी रिपॉज़िटरी का पेज खोलें और आज की तरह `Code` से `Codespaces` चुनें. सूची में आज बनाया गया Codespace दिखेगा; उसे चुनें. नया Codespace न बनाएँ.
2. फ़ाइल सूची में `pre_day2/template.md` नाम की नई फ़ाइल बनाएँ. बनाने का तरीका अगले भाग में है.
3. नीचे "template.md" वाले बॉक्स की सामग्री कॉपी करके चिपकाएँ और आज की तरह सहेजें.
4. इसी तरीके से `pre_day2/generate.sh` भी बनाएँ और सहेजें.
5. दोनों फ़ाइलें खोलकर उनकी सामग्री की तुलना इस पेज के बॉक्स से करें.

इस बार नई ब्रांच बनाए बिना `master` पर ही काम कर सकते हैं. कमिट अगले सत्र में करेंगे.

## नई फ़ाइल कैसे बनाएँ (आज के अभ्यास में यह प्रक्रिया नहीं की गई थी)

1. फ़ाइल सूची में सबसे ऊपर अपनी रिपॉज़िटरी के नाम वाली पंक्ति पर दायाँ क्लिक करें (नाम बड़े अक्षरों में दिखता है).
2. खुले मेन्यू से `New File...` (नई फ़ाइल) चुनें. नाम दर्ज करने का बॉक्स दिखेगा.
3. `pre_day2/template.md` दर्ज करें और Enter दबाएँ. `pre_day2` फ़ोल्डर और उसके भीतर फ़ाइल एक साथ बन जाएँगे, और संपादन के लिए खाली पेज खुलेगा.

यदि स्क्रीन अलग दिखती है, तो फ़ाइल सूची में "नई फ़ाइल" वाला विकल्प खोजें. फ़ाइलों के नीचे की खाली जगह पर दायाँ क्लिक करने से भी वही मेन्यू खुलता है. Codespace में फ़ाइलों का संपादन VS Code नाम के एडिटर में होता है. आधिकारिक स्क्रीन परिचय: [User Interface — Explorer (VS Code Docs)](https://code.visualstudio.com/docs/editing/getting-started/userinterface#_explorer-view)

## चिपकाने के लिए सामग्री

केवल बॉक्स के अंदर की सामग्री चिपकाएँ. फ़ाइल का नाम या बॉक्स बनाने वाले चिह्न शामिल न करें. इसे टर्मिनल में न चिपकाएँ. इस बार इसे चलाना नहीं है.

### template.md

```markdown
# वेब पेज की जाँच रिपोर्ट

लक्षित पेज: https://example.com/
जाँच की तारीख और समय (UTC): {{CHECKED_AT}}
HTTP स्थिति कोड: {{HTTP_STATUS}}

यह रिपोर्ट टेम्पलेट और जाँच के परिणाम से बनाई जाती है.
```

### generate.sh

```sh
#!/bin/sh

# यह स्क्रिप्ट वेब पेज की जाँच के परिणाम से रिपोर्ट बनाती है.
# पहली पंक्ति में #! का अर्थ है कि इस फ़ाइल की सामग्री sh नाम के प्रोग्राम से चलाई जाए.
# # से पंक्ति के अंत तक का पाठ केवल समझाने के लिए है; वह चलाया नहीं जाता.

# बीच में कोई त्रुटि आने पर उसी समय रुक जाएँ (-e).
# ऐसे मान का उपयोग करने पर भी रुक जाएँ जो अभी निर्धारित नहीं है (-u).
set -eu

# उस फ़ोल्डर में जाएँ जिसमें यह स्क्रिप्ट रखी है.
# $0 इस फ़ाइल का अपना पथ है; dirname उस पथ से केवल फ़ोल्डर का नाम निकालता है.
# इससे स्क्रिप्ट कहीं से भी चलाने पर उसके पास रखी template.md को उसी तरह पढ़ा जा सकता है.
cd "$(dirname "$0")"

# case चलाते समय दिए गए आर्ग्युमेंट की संख्या के अनुसार अलग प्रक्रिया चुनता है.
# $# चलाते समय दिए गए आर्ग्युमेंट की संख्या है.
case "$#" in
  # 0 का अर्थ है कि चलाते समय कोई आर्ग्युमेंट नहीं दिया गया.
  0)
    # [1] वेब पेज पर अनुरोध भेजें और HTTP स्थिति कोड http_status में रखें.
    #     विफलता को त्रुटि मानें, 30 सेकंड बाद अनुरोध रोक दें और उत्तर का मुख्य भाग न सहेजें.
    http_status=$(curl --fail --silent --show-error --location --max-time 30 \
      --output /dev/null --write-out '%{http_code}' https://example.com/)

    # [2] जाँच की तारीख और समय UTC में checked_at में रखें.
    checked_at=$(date -u '+%Y-%m-%d %H:%M:%S UTC')

    # [3] template.md के दो प्लेसहोल्डर को ऊपर के मानों से बदलें और report.md में लिखें.
    #     विभाजक के लिए | का उपयोग किया गया है ताकि मान में / होने पर भी कमांड सही चले.
    sed -e "s|{{CHECKED_AT}}|$checked_at|g" \
        -e "s|{{HTTP_STATUS}}|$http_status|g" template.md > report.md

    printf '%s\n' 'report.md बना दी गई है.'
    # ;; इस स्थिति की प्रक्रिया समाप्त करता है.
    ;;

  # 1 का अर्थ है कि चलाते समय एक आर्ग्युमेंट दिया गया.
  1)
    # $1 चलाते समय दिया गया पहला आर्ग्युमेंट है.
    if [ "$1" != "setup-actions" ]; then
      printf '%s\n' 'उपयोग: ./generate.sh या ./generate.sh setup-actions' >&2
      exit 2
    fi
    # स्वचालित रूप से चलाने की सेटिंग रखने का फ़ोल्डर बनाएँ. पहले से मौजूद हो तो उसी का उपयोग करें.
    mkdir -p ../.github/workflows
    # अगली पंक्ति से WORKFLOW वाली पंक्ति के ठीक पहले तक की सामग्री ज्यों की त्यों फ़ाइल में लिखें.
    cat > ../.github/workflows/update-report.yml <<'WORKFLOW'
name: Update report

on:
  push:
    branches: [master]
    paths:
      - pre_day2/template.md
      - pre_day2/generate.sh
      - .github/workflows/update-report.yml
  workflow_dispatch:

permissions:
  contents: write

jobs:
  update-report:
    runs-on: ubuntu-latest
    steps:
      - name: Check out the repository
        uses: actions/checkout@v7

      - name: Check required tools
        run: |
          command -v sh
          command -v sed
          command -v date
          command -v curl

      - name: Generate the report
        run: |
          chmod +x pre_day2/generate.sh
          ./pre_day2/generate.sh

      - name: Commit the changed report
        run: |
          if [ -z "$(git status --porcelain -- pre_day2/report.md)" ]; then
            echo "report.md में कोई बदलाव नहीं है."
            exit 0
          fi
          git config user.name "github-actions[bot]"
          git config user.email "41898282+github-actions[bot]@users.noreply.github.com"
          git add pre_day2/report.md
          git commit -m "chore: update report"
          git push
WORKFLOW
    # स्क्रीन पर बताएँ कि फ़ाइल लिख दी गई है.
    printf '%s\n' '.github/workflows/update-report.yml बना दी गई है.'
    ;;

  # * का अर्थ है कि ऊपर की दोनों स्थितियों में से कोई भी लागू नहीं है.
  *)
    printf '%s\n' 'उपयोग: ./generate.sh या ./generate.sh setup-actions' >&2
    exit 2
    ;;
# esac पूरे case को समाप्त करता है.
esac
```

## पूरा होने पर स्थिति

- फ़ाइल सूची में `pre_day2` के अंदर दो फ़ाइलें हों और उन्हें खोलने पर सामग्री इस पेज के बॉक्स जैसी हो.
- आज के अभ्यास में बदली हुई फ़ाइलों के नाम जाँचने के लिए जो प्रक्रिया अपनाई थी, उसे दोहराने पर `pre_day2/` दिखे. ये नई फ़ाइलें हैं, इसलिए आज से अलग शीर्षक के नीचे दिखेंगी; `pre_day2/` दिखना पर्याप्त है. फ़ाइलें सहेजी गई हैं, लेकिन अभी कमिट नहीं की गई हैं. कमिट अगले सत्र में करेंगे, इसलिए इस बार यहीं तक करना है.
- अगला सत्र इसी Codespace से शुरू करेंगे. Codespace को हटाए बिना रखें. यदि Codespace हट गया हो, तो आज के ही तरीके से नया बनाएँ और इस पेज के निर्देशों से दोनों फ़ाइलें भी दोबारा बनाएँ.
