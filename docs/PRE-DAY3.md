# अगले सत्र की तैयारी का कार्य

इस कार्य में पिछली बार तैयार की गई `pre_day2/template.md` और `pre_day2/generate.sh` का उपयोग होगा. इस कार्य में कुल लगभग 30 मिनट लगेंगे. कुछ जमा नहीं करना है. कार्य के बाद "अगले सत्र की तैयारी" भी है, जिसमें अगले सत्र में इस्तेमाल होने वाली बड़ी फ़ाइलें पहले से डाउनलोड करनी हैं. यह अलग काम है और इन 30 मिनट में शामिल नहीं है.

## कार्य

रिपोर्ट में "स्क्रिप्ट चलाने वाली मशीन" का फ़ील्ड जोड़ें. फिर अपने Codespace और GitHub Actions, दोनों में रिपोर्ट बनाएँ और दर्ज हुए दो मानों की तुलना करें. GitHub का परिणाम लाने पर Codespace में बनाया गया मान बदल जाएगा, इसलिए उसे पहले कहीं नोट कर लें.

इसमें वही क्रियाएँ इस्तेमाल होंगी जो आज के अभ्यास में की थीं. इन शर्तों का पालन करते हुए काम करें.

- आज की तरह `master` से कार्य के लिए नई ब्रांच बनाएँ और उसमें काम करें.
- बदलावों को Pull Request के ज़रिए `master` में मर्ज करें.
- केवल `pre_day2` की तीन फ़ाइलें `template.md`, `generate.sh` और `report.md` कमिट करें.
- मर्ज करने के बाद GitHub का परिणाम Codespace की `master` ब्रांच में भी लाएँ.

## जोड़ने वाली पंक्तियाँ

जोड़ने वाली पंक्तियाँ नीचे दिए बॉक्स में हैं. बॉक्स की सामग्री बताई गई जगह पर ज्यों की त्यों लिखें.

### template.md

इसे "जाँच की तारीख और समय (UTC)" वाली पंक्ति के बाद जोड़ें.

```
स्क्रिप्ट चलाने वाली मशीन: {{MACHINE_NAME}}
```

### generate.sh

इसे `checked_at=` वाली पंक्ति के बाद जोड़ें. `#` से शुरू होने वाली पंक्तियाँ बताती हैं कि कोड क्या कर रहा है.

```
    # जिस मशीन पर स्क्रिप्ट चल रही है, उसका पहचान नाम machine_name में रखें.
    # /proc/sys/kernel/hostname वह फ़ाइल है जिसमें मशीन अपना पहचान नाम रखती है.
    machine_name=$(cat /proc/sys/kernel/hostname)
```

`{{HTTP_STATUS}}` को बदलने वाली `sed` पंक्ति से पहले यह एक पंक्ति जोड़ें. यह `template.md` में जोड़े गए `{{MACHINE_NAME}}` प्लेसहोल्डर को ऊपर निकाले गए पहचान नाम से बदलने का निर्देश है.

```
        -e "s|{{MACHINE_NAME}}|$machine_name|g" \
```

यह पंक्ति अपने पहले और बाद की `sed` पंक्तियों के साथ मिलकर एक ही कमांड बनाती है. पंक्ति के अंत का `\` (बैकस्लैश) बताता है कि "कमांड अगली पंक्ति में जारी है", इसलिए इसे ज़रूर शामिल करें. इस पंक्ति के ठीक पहले या बाद में व्याख्या वाली पंक्तियाँ न जोड़ें. कमांड के बीच में ऐसा करने से वह वहीं टूट जाएगी.

## ध्यान देने योग्य बातें

- `generate.sh` में जोड़ी गई `sed` पंक्ति के अंत का `\` न हटाएँ. इसे हटाने पर `./generate.sh` बिना कुछ दिखाए अटक जाएगी. ऐसा हो तो `Ctrl` दबाए रखते हुए `C` दबाकर रोकें, `\` वापस जोड़कर फ़ाइल सहेजें और फिर से चलाएँ.
- Actions में कोई चरण लाल हो जाए, तो सबसे पहले लाल हुए चरण की त्रुटि पढ़ें. अक्सर कारण जोड़ी गई पंक्तियों को गलत कॉपी करना या गलत जगह जोड़ना होता है. Pull Request पहले ही मर्ज हो चुकी होगी, इसलिए उसी Pull Request से सुधार नहीं कर सकते. अपनी `master` को अद्यतन करें, नई ब्रांच बनाएँ, उसमें सुधार करें और उसी प्रक्रिया से फिर मर्ज करें.
- Codespace और GitHub Actions के मान अलग होने चाहिए. यदि एक जैसे हों, तो जाँचें कि उन्हें नोट करते समय कोई गलती तो नहीं हुई.

## स्वयं जाँचें

नीचे दी गई सभी शर्तें पूरी हों, तो कार्य पूरा है. जाँचने के तरीके भी दिए गए हैं; एक-एक करके जाँचें.

- [ ] कार्य की ब्रांच से Pull Request के ज़रिए बदलाव मर्ज किए गए हैं और बदली हुई फ़ाइलें केवल `pre_day2` की तीन फ़ाइलें हैं. (उस Pull Request के `Files changed` में जाँचें.)
- [ ] GitHub Actions में रिपोर्ट सफलतापूर्वक बनी है. (रिपॉज़िटरी के `Actions` में, मर्ज के बाद शुरू हुआ `Update report` रन हरा दिखे. मर्ज के तुरंत बाद रन जारी होता है, इसलिए उसके पूरा होने तक प्रतीक्षा करें.)
- [ ] GitHub का परिणाम Codespace की `master` में लाया जा चुका है. (`git status` चलाने पर `master` ब्रांच दिखे और कोई ऐसा बदलाव न हो जो कमिट नहीं किया गया है.)
- [ ] `report.md` में "स्क्रिप्ट चलाने वाली मशीन: " वाली पंक्ति है और उसके बाद मान दिया गया है. (`cat pre_day2/report.md` से दिखाएँ और जाँचें कि पंक्ति मौजूद है तथा मान अभी भी `{{MACHINE_NAME}}` नहीं है.)
- [ ] यह मान Codespace में रिपोर्ट बनाते समय नोट किए गए मान से अलग है. (लाई गई `report.md` का मान GitHub Actions में बनाया गया है.)

## अगले सत्र की तैयारी

यहाँ से आगे का काम अगले सत्र की तैयारी है और ऊपर के कार्य से अलग है. अगले सत्र में इस्तेमाल होने वाली बड़ी फ़ाइलें पहले से डाउनलोड कर लें.

तैयारी का प्रोग्राम `pre_day3/prepare.sh` रिपॉज़िटरी में शुरू से मौजूद है. Codespace के टर्मिनल में रिपॉज़िटरी के मूल फ़ोल्डर से यह कमांड चलाएँ.

```sh
./pre_day3/prepare.sh
```

इसमें कुछ मिनट लग सकते हैं. `तैयारी पूरी हो गई है` दिखने पर काम पूरा है. त्रुटि के कारण रुकने पर स्क्रीन पर बताए गए अगले कदमों का पालन करें (कुछ देर प्रतीक्षा करें, खाली जगह बनाएँ, फिर से चलाएँ आदि).

यदि समय न मिलने से अभी इसे नहीं चला पाएँ, तो अगले सत्र की शुरुआत में यही कमांड चलाकर आगे बढ़ सकते हैं. हालाँकि डाउनलोड में लगभग 10 मिनट तक लग सकते हैं, इसलिए अगले सत्र के लिए इतना अतिरिक्त समय रखें.

अगले सत्र में इस बार दर्ज की गई "स्क्रिप्ट चलाने वाली मशीन" की व्यवस्था को Docker के अंदर चलाएँगे.
